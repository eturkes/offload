# offload contract — IMPLEMENT units

Predicates = testable; ids (`C3`, `S7`…) are cited by tests + review rows. Tier per unit. `Decisions` (spec) outrank this file; a conflict = a defect here.

Scope: one controller (this machine) drives the pool; pool hosts are distinct machines; the source tree stays quiescent during an upload, and an image definition during its hash + build (offload takes no snapshot).

## CLI — tier kernel

- C1 `offload run [--local|--pool] [--host NAME] [--gpu] [--no-sync] [--get PATH]… [--] CMD [ARG…]`; `offload status`; `-h`/`--help` on both. Flags parse up to `--` or the first non-flag word; everything after belongs to CMD.
- C2 `--local` with any of `--pool`, `--host`, `--gpu`, `--no-sync`, `--get` → usage error. `--host`, `--gpu`, `--no-sync`, `--get` imply `--pool`.
- C3 Exit status precedence (`run`; `ctr` = K2, K7, K10): offload got HUP/INT/TERM → 129/130/143; else an offload failure → 125 (sync up/down failed, remote setup failed, worktree or unsupported repo layout under `--pool`, every host up and none with a GPU under `--gpu`); else the command's status unchanged (any value, 2/125/255 included; 128+n when signal n killed it; 127 = not found, 126 = not executable). Usage errors, an invalid pool file, an unknown `--host` → 2 before any work.
- C4 stderr carries every offload message, prefixed `offload: `; stdout carries the command's output alone (`status` prints to stdout).
- C5 Placement line on stderr before the command starts: `offload: local slot <i>/<n>` | `offload: <host> slot <i>/<n> (<cpus> CPUs, <busy>% busy) → ~/<workdir>` (busy = 100 × load/nproc, rounded).

## Pool file — tier data

- P1 Path = `$OFFLOAD_CONFIG`, else `$XDG_CONFIG_HOME/offload/pool.toml`, else `~/.config/offload/pool.toml` (empty env values count as unset).
- P2 `[[host]]` tables: `name` (required, `[A-Za-z0-9._-]+`, not `.`/`..`, unique), `address` (required, `[user@]host` or an ssh_config alias: no whitespace, `/`, `:`, leading `-`; unique), `slots` (int ≥ 1, default 2), `multiplex` (bool, default false). Unknown keys → error naming them. A present file is validated on every `run` (bad file → rc 2) except under `--local`, which never reads it.
- P3 Missing file: `run` → local slots only + one stderr note; `run --pool` + `status` → rc 2 naming the path. A file without hosts = an invalid file.

## Probe + status — tier data

- R1 One ssh round trip per host (shared SSH options, X5), all hosts in parallel, ≤ 8 s end to end, killed + reaped at the deadline: nproc (int ≥ 1), 1-min loadavg (finite ≥ 0), MemAvailable kB (int ≥ 0), NVIDIA GPU count (int ≥ 0). Nonzero ssh exit, timeout, or output ≠ exactly those 4 fields → host `down` with the reason; never a crash.
- R2 `status`: local heavy slots (held/total + `heavy --status`-style holder lines) then one row per host in pool-file order: state, slots held/total, CPUs, load, busy %, free memory, GPUs; a down host shows its reason. A slot counts as held by its lock alone (stale owner text ignored). rc 0 with hosts down.

## Slots — tier kernel

- S1 Local slots = heavy's: dir `${XDG_RUNTIME_DIR:-/tmp}/heavy`, files `slot1…slotN`, N = `HEAVY_SLOTS` (unset/empty = 2) accepted + rejected exactly as heavy does (differential test vs a copy of heavy).
- S2 Acquire = open `slot<i>` (create, never unlink) + flock(2) `LOCK_EX|LOCK_NB`, i ascending; first success wins. heavy (and `flock -n`) and offload exclude each other on the same file. Contention ≠ I/O error (the latter → 125).
- S3 While held, `slot<i>.owner` = `<pid> since <HH:MM:SS>:` + ` <word>` per CMD word, shell-quoted; emptied before unlock. The command never inherits a lock fd.
- S4 Pool slots = same mechanism under `${XDG_RUNTIME_DIR:-/tmp}/offload/hosts/<name>/slot<i>`, i = 1…`slots`; owner text = ` <host>: <root> <CMD…>`. Controller workdir lock `…/hosts/<name>/wd-<workdir name>.lock` taken non-blocking; busy → host unavailable this round (its slot released, never held while waiting).
- S5 A local run's heavy slot stays held until the watcher (X1) finishes tearing down the command, even if offload dies first. A remote run's controller locks may free early on offload death; workdir safety then rests on the remote lock (Y11).
- S6 Lock directories (heavy's dir, `offload/hosts/<name>`, `offload/ctr`): offload creates each missing component below the runtime dir (`$XDG_RUNTIME_DIR`, else `/tmp`) with mode 0700; every component — existing or new — must be a real directory (no symlink) owned by the effective uid without group or other write, else 125 naming it, before any lock file is opened (under the `/tmp` fallback another user could pre-create one and share or read the locks). The runtime dir itself is created (0700) if missing, never checked.

## Placement loop — tier kernel

- L1 Eligibility: local unless pool-only (`--pool` or implied); pool unless `--local`, missing pool file, or remote-ineligible tree (Y3).
- L2 Round, pool first (the controller stays free for the owner): among eligible hosts (`--host` = that one) with a free slot + free workdir lock, probe (≤ 8 s), keep up hosts (with ≥ 1 GPU under `--gpu`), pick the lowest load/nproc (ties → pool-file order), acquire its slot non-blocking (lost race → next round); else a local slot. A signal during the round → no local slot taken.
- L3 Nothing acquired → one `offload: waiting …` line naming held/total per place; next round 2 s after the previous ends; a down host is re-probed at most every 30 s. INT/TERM/HUP while waiting → 130/143/129, nothing held.
- L4 `--gpu` with every eligible host up and none showing a GPU → 125. Hosts down or busy → keep waiting.

## Sync — tier kernel

- Y1 Sync root = `git rev-parse --show-toplevel` when cwd is inside a git work tree, else cwd ("plain"). A git error other than "not a git repository" → 125, never plain mode; "not a git repository" with a `.git` entry in cwd or any ancestor (a damaged repo) → 125 too. CMD runs in `<workdir>/<cwd relative to root>`. A root that is `/` or the home directory is local-only (`--pool` → 125); every transfer refuses a root that is not absolute or is `/`.
- Y2 Workdir = `offload/<basename(root), chars outside [A-Za-z0-9._-] → _>-<first 8 hex of sha1(abs root)>` under the remote `$HOME`; meta dir = `offload/.meta/<workdir name>/`.
- Y3 Remote-eligible git layouts: a main worktree (`.git` = a directory at the root, git dir = common dir) or a linked worktree (git dir = `<common dir>/worktrees/<id>`, `<id>` in `[A-Za-z0-9._-]`, common dir a directory); either with no `objects/info/alternates`, no gitlink in the index, no untracked nested repository. Anything else (external git dir, submodules, nested repo, alternates, an unusual worktree id) → local slots only; under `--pool` → 125 naming the reason. Checked before any remote work.
- Y4 Git upload: U = `git ls-files -z -co --exclude-standard` at root, entries that exist (lstat; a non-ENOENT lstat error → 125) below real-directory ancestors (a path reached through a symlink is not in the tree), + every self-ignored `.gitignore` in a non-ignored directory. rsync sends U (non-recursive: files + symlinks) and mirrors `.git` (recursive, `--delete` inside `.git`, `*.lock` never sent). Every tracked file crosses whatever the ignore rules say; every ignored untracked file stays local. Linked worktree: the common dir mirrors to `<META>/repo/` instead (same `--delete`, no `*.lock`), carrying `worktrees/<id>/` alone among the admin dirs, minus its `gitdir` + `commondir` files; before CMD (under the remote lock) the run script writes them for the host (`<remote workdir>/.git`, `../..`) and makes the workdir's `.git` the gitfile `gitdir: <remote META>/repo/worktrees/<id>` ⇒ the host sees that worktree's HEAD, index + per-worktree refs over the shared objects + refs. A workdir already holding a `.git` directory → 125. Every transfer compares mtimes to the nanosecond (`--modify-window=-1`; both rsyncs ≥ 3.1.3): a same-size rewrite within the same second still crosses. U, D + plain-mode files compare by content (`--checksum`): a rewrite keeping size + mtime (fixed-mtime tools: cargo vendor) still crosses both ways; `.git` + `--get` keep the size + mtime check.
- Y5 Git remote prune (before CMD, under the remote lock): R = remote `git ls-files -z -co --exclude-standard` with the local global excludes file supplied; delete each path in R − U whose every ancestor below the workdir is a real directory (no symlink) and which is itself a file or symlink (never a directory; never recursive). U reaches the remote on stdin as NUL-terminated records after the run script (X8): the run nonce, the global excludes content (each line cut at its first NUL — git's own pattern boundary — so the record holds none), then COUNT paths; a count/nonce mismatch, a git failure or a missing `.git` → 125 before any prune deletion (the `.git` mirror may already have changed).
- Y6 Git download (after CMD, any status): D = remote `git ls-files -z -co --exclude-standard`, filtered to existing paths below real-directory ancestors; rsync D → local with `--update` (a regular file newer locally stays; symlinks + type changes take the remote version), no deletes. `.git` and ignored untracked files never return.
- Y7 Plain mode: upload = mirror with `--delete` + rsync `--filter=':- .gitignore'` (rsync's dir-merge semantics, not git's); download = `--update` + same filter.
- Y8 `--get PATH` (repeatable; relative to the invocation cwd; must stay inside the sync root after normalization; `.git` + absolute paths refused → rc 2): after the automatic download, PATH copied remote → local with `--update` whatever its ignore status; trailing `/` = directory contents. Missing remote PATH → 125.
- Y9 `--no-sync`: no upload, prune or automatic download; workdir created if absent; `--get` still runs.
- Y10 Upload/prune/download/get failure → 125 with the tool's message; CMD never starts after a failed upload or prune. Interrupted runs (C3 signals) skip every download.
- Y11 Remote lock: every remote phase of a run (upload rsync via `--rsync-path`, the run script, download rsyncs) holds flock on `<meta dir>/lock`, waiting ≤ 300 s (then 125); the run script keeps it until X1's teardown ends ⇒ a successor never syncs into a workdir with a live predecessor.

## Execution — tier kernel

- X1 CMD runs under a watcher in a new session (setsid), stdin `/dev/null`, default INT/QUIT dispositions, and — where the user's systemd manager (socket under `$XDG_RUNTIME_DIR`, else `/run/user/<uid>`) starts it — in its own transient scope `offload-<watcher pid>-<random>.scope` (`systemd-run --user --scope --expand-environment=no` execs CMD in place: same pid, argv, cwd, stdio; `XDG_RUNTIME_DIR` + `INVOCATION_ID` restored as CMD had them). Scopes need cgroup v2. CMD is exec'd only after its cgroup is recorded (a mark file in the manager's runtime dir, removed after teardown; a SIGKILLed watcher leaves it there, cleared with the user's session); a scope that never started leaves CMD unstarted, so CMD then starts without one, after one `offload: <host>: no systemd scope` stderr line (systemd-run's own errors stay off stderr). The watcher holds offload's pipe; at EOF (TERM/HUP to the watcher count as EOF), or when CMD's leader exits, it sends TERM to every process in that session (`pkill -s`) and that scope (`systemctl --user kill`), KILL after 10 s, and exits once the session is empty and the scope's cgroup is unpopulated (cgroup v2 `cgroup.events`). Without a scope, a process that starts its own session escapes (documented limit); with one, a process another systemd unit adopts escapes. A nested offload run's command ends with the outer run: the outer teardown's TERM reaches the inner watcher (a TERM-ignoring inner command can outlive it, as the outer KILL may end the inner watcher first).
- X2 Local: argv executed as given (no shell), cwd unchanged, env inherited (names beginning `__` = the watcher's own, reserved); the command looked up as bash does (a name with `/` = that path; else the first executable regular file on PATH): nothing there → 127, something there that cannot run (a PATH match alone non-executable, a directory) → 126, before any slot is taken. Remote: CMD words shell-quoted into `bash -lc` (login env ⇒ host PATH).
- X3 Offload on HUP/INT/TERM: close the watcher pipe, wait for the watcher to finish, skip downloads, release locks, exit 129/130/143.
- X4 Output streams live, byte-exact (no buffering or rewriting by offload).
- X5 Every ssh + rsync connection: BatchMode=yes, StrictHostKeyChecking=accept-new, ConnectTimeout=5, ServerAliveInterval=15, ServerAliveCountMax=4, ForwardAgent=no, ForwardX11=no, ClearAllForwardings=yes (command-line values beat ssh_config ⇒ a `Host *` default never forwards the controller's agent, display or ports to a pool host). Pool hosts set sshd ClientAliveInterval 15 × 4 ⇒ a vanished controller's session ends within ~1 min (X1 teardown follows). `multiplex = true` adds `-o ControlMaster=auto -o ControlPath=<dir>/%C -o ControlPersist=60` to every connection to that host (probe, upload, run, status lookup, download, `--get`), dir = `$XDG_RUNTIME_DIR/offload/ssh` created 0700; a dir that is unset, holds characters outside `[A-Za-z0-9/._-]`, exceeds 49 bytes or refuses new files (socket path + OpenSSH's temporary suffix ≤ 107) → that run connects plainly after one stderr note. A killed client closes its session, so EOF (X1) still follows; the master lives on 60 s idle. Every ssh call, rsync's included, passes `-T` (no tty, whatever ssh_config says).
- X6 Remote status vs transport: the run script records `<nonce> <status>` in the meta dir; ssh exit 255 → offload reads that record (one extra ssh): matching nonce → the command's 255; else transport failure → 125.
- X8 Remote launch: the ssh command = `bash -c BOOT offload N SHA256 WORKDIR META SUB MODE NONCE COUNT CMD` (MODE = git | worktree:<id> | plain | nosync). BOOT takes N stdin bytes (watch.bash + remote.bash; GNU `head -c` never reads past them) into a temporary file, checks its sha256, renames it to `<META>/run-<first 16 hex of SHA256>.bash` and execs `bash <that file> WORKDIR META SUB MODE NONCE COUNT CMD`; a short, corrupt or unwritable copy, or a directory at that name, → 125 before any script or CMD runs (a file already at that name never runs instead). A remote `ps` shows that path + those words, never the script body or the excludes. Variables in both scripts are named `__…` (X2).
- X7 Requirements: controller = ssh, rsync, git, bash, util-linux (`setsid`), procps (`pkill`/`pgrep`); pool host = bash, rsync, git, GNU coreutils (`sort -z`, `comm -z`, `head -z`), util-linux (`setsid`, `flock`), procps. Scope teardown (X1), either side = a systemd ≥ 254 user manager + cgroup v2; absent ⇒ session teardown alone.

## Image runs — tier kernel

- K1 `offload ctr [--] CMD [ARG…]` | `offload ctr --layers` | `offload ctr --check`; `-h`/`--help` reached by the flag parser (help wins over the switch + project problems; an earlier unknown flag stays a usage error). Flags parse up to `--` or the first non-flag word; CMD words after it stay verbatim. `--layers` + `--check` take no CMD and exclude each other; a usage error → 2. First words beginning `__` are offload's own (`offload __ctr-init`, K8).
- K2 Switch `OFFLOAD_CTR`: unset, empty or `0` → CMD replaces offload in place (execve: same pid, argv, cwd, env, stdio; lookup as X2: nothing there → 127, something that cannot run or an exec refusal (ENOEXEC included) → 126); no project, pool file or podman is read. `1` → image run (K3–K8). Any other value → 2 naming the variable. `--layers` + `--check` ignore it.
- K3 Root = Y1's sync root (git toplevel, else the cwd; a damaged repo or another git error → 125), symlink-resolved, as is the cwd. Definition = `<root>/.devcontainer/Containerfile`, a regular file in a real directory — neither a symlink (else → 2 naming the path); build context = that directory. Setup (git included) runs under K8's signals. A mounted path holding `:` (podman's `-v` separator) → 125 naming it.
- K4 Tag = `localhost/offload-ctr:<16 hex>` of a sha256 over the context tree (every entry below the context dir, each length-framed as kind + permission bits `mode & 07777` + relative path + content: file bytes, symlink target; encoding + order = mechanism). Observable: equal trees → equal tags on every host; a change of content, name, permission bits, link target or entry kind, or an entry added or removed → a new tag (COPY keeps permissions); owners + mtimes never count (COPY sets root, `--timestamp 0` fixes times). A symlinked or non-directory context root, another file type or an unreadable entry → 125.
- K5 Build on miss: `podman image exists` 0 = present, 1 = absent → stderr `offload: building <tag> from <definition>`, then `podman build --timestamp 0 -t <tag> -f <definition> <context>`; its output captured, printed to stderr on failure (→ 125); any other `exists` result → 125. One build per tag per host at a time: lock `<runtime dir>/offload/ctr/<16 hex>.lock` (flock, symlinks never followed, directories per S6), existence re-checked once held; podman build inherits the lock ⇒ it stays held until the build ends, even past offload's death. Any K8 signal during setup, build or the lock wait → build stopped (TERM), exit 128+n.
- K6 Run: `podman run --rm --pull=never --pid=private --userns=keep-id --log-driver=none --http-proxy=false -i --preserve-fds=1 --entrypoint /.offload/init -v <offload binary>:/.offload/init:ro -v <root>:<root> [-v <git common dir>:<git common dir> when outside root] -v <home>:/.offload/home -e HOME=/.offload/home --passwd-entry <user entry, home /.offload/home> -w <cwd> <tag> __ctr-init CMD…`; CMD words verbatim (no shell); stdin = `offload ctr`'s stdin; fd 3 in the container = the control socket. The image's ENV applies, the host's environment does not (proxy variables included); its ENTRYPOINT, CMD, USER + WORKDIR do not. `<home>` = `${XDG_CACHE_HOME:-~/.cache}/offload/ctr/<Y2 name of root>/home`, created 0700, kept across runs + images, shared by concurrent runs of the root ⇒ tool state under HOME persists per host + root (the image routes writable tool state there). Files CMD writes in the mounts belong to the invoking user. Output streams live (X4), never copied into a container log. The mounted binary = the running one (same inode, checked just before launch; replaced → 125).
- K7 Status: the init writes one record `<status>\n` on the control socket before its exit; `offload ctr` waits for podman, then exits with that status unchanged (any value; 128+n when signal n killed CMD; in the image, lookup as X2: 127 | 126), whatever podman's own exit status. No complete record within 1 s of podman's exit (podman missing, failing or killed while the container lives, image gone, container never started, init refused or gone) → 125 with an offload message.
- K8 Signals + teardown: podman runs in its own session (a terminal's signals reach `offload ctr` alone; no controlling terminal ⇒ a terminal stdin never stalls it) and — where the user's systemd manager starts a transient scope (probed per run: `systemd-run --user --scope -- true`) — in a scope of its own (probe under K8's signals, ≤ 5 s, else plain), the caller's `INVOCATION_ID` kept from podman (with it podman keeps conmon in the caller's unit; inside its scope systemd-run sets the scope's own) ⇒ no signal X1 aims at its session or scope reaches podman or conmon (podman dies on TERM: always on a second, at times on a first). Once podman runs, each HUP, INT, QUIT, TERM, USR1 + USR2 delivered to `offload ctr` goes to the init over the control socket (one byte = the signal number; bytes sent before CMD starts are delivered right after), which sends it to CMD's process group (CMD leads its own) ⇒ CMD's group receives each delivered signal once, as CMD would natively; the init drops those signals arriving any other way (podman's sig-proxy, a scope-wide kill of podman). The init refuses to run unless it is PID 1 (→ no record). It reaps every process; when CMD exits it TERMs every remaining process, writes the record once none remain or 10 s have passed, then exits (= KILL of the pid namespace). CMD never inherits fd 3. The control socket = liveness: `offload ctr` gone (any signal, SIGKILL included) → the init exits at once ⇒ every container process dies (KILL, no TERM first), the container is removed. podman gone first → no record → 125, and `offload ctr`'s exit ends the container. Under `offload run`, X1's TERM reaches CMD through `offload ctr`, X1's KILL ends the container through liveness; the container dies before X1's watcher can observe its session empty (≥ 100 ms after its KILL), so slots + locks (S5, Y11) free after the container's last write — barring an init that cannot run (stopped, frozen) or a container process stuck in uninterruptible I/O (documented limit).
- K9 `--layers`: build on miss (K5); stdout = the image's `RootFS.Layers` digests in order, one per line (none = zero lines), printed only after a successful inspect; failure → 125; a K8 signal → 128+n.
- K10 `--check`: pool file per P1 (missing or invalid → 2), then the local definition (K3 → 2/125) + layers (K9; failure → 125, no remote work). Then every pool host in parallel: a host the probe (R1) finds down → `failed (down: <reason>)`; else `offload run --host <h> --` (sync per Y4–Y7; waits for a slot; Y3 + run failures → `failed (rc <r>)`) running, under `bash`, the host's installed offload: lines framed with a per-host random nonce, `offload-check <nonce> <sha256 of its binary>` + `layer <nonce> <digest>` per layer; other output (a login shell's) never counts. One stdout line per host in pool-file order: `<host>: same (<n> layers)` | `<host>: different (here <n>, there <m> layers)` | `<host>: failed (…)`, + `; offload binary differs` when the sha256 differs from this binary's; exit 0 when every host is `same` with the same binary, else 1; a K8 signal → 128+n. Equality = the complete ordered digest list; image config (ENV, …) + HOME contents lie outside it. Remote stderr passes through.
- K11 Requirements: Linux with a local (non-remote) rootless podman ≥ 5.7 and subordinate uid + gid ranges for the user (keep-id); the offload binary static (`CGO_ENABLED=0`: it is the init inside images of any libc) + of the image's architecture.
