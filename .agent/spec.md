## Intent

A simple CLI for personal use to offload heavy compute work, at a moment's notice, to any available machine within a designated pool of machines accessible within the local network via SSH. Whenever a pool machine is idle, it works on an indefinite task that I designate for it.

## Decisions

- Stack = Go, one static binary; shells out to `ssh`, `rsync`, `git`. License = Apache-2.0 WITH LLVM-exception (`LICENSE` + `NOTICE`, as cnl-ckc).
- User = agents alone (owner never calls it). Trigger = hybrid `offload run [--local|--pool] -- <cmd>`: the agent opts a command in (= offloadable: project-scoped, untimed; controller-only = dGPU, desktop, BrowserOS Neo); the tool runs it in a free pool slot, else a free local `heavy` slot, else waits on both (one waiting message); stderr names where it ran. Pool first: the controller (t25-480) stays free for the owner's on-demand work; load ranks pool hosts alone (nixbox's idle task keeps its load up). `--host`, `--gpu`, `--no-sync` imply `--pool`; `--gpu` = pool hosts with an NVIDIA GPU; dGPU work = `gpu-run`. Timing-recorded runs stay on plain `heavy`.
- `heavy` interop: offload takes heavy's slots itself — `${XDG_RUNTIME_DIR:-/tmp}/heavy/slot<i>`, i = 1…`HEAVY_SLOTS` (default 2), flock(2) exclusive non-blocking, owner line `<pid> since HH:MM:SS: <cmd %q>` in `slot<i>.owner`, emptied at exit ⇒ `heavy --status` lists offload's local runs. `heavy` stays a separate host script.
- Admission = per-host `slots` in the pool file (default 2); slot locks on the controller (`${XDG_RUNTIME_DIR}/offload/hosts/<name>/slot<i>`). Loadavg ranks hosts with a free slot (score = 1-min load / nproc), never admits: an idle task's threads inflate it.
- Remote run = pick host → sync up → `bash -lc` the command in the remote workdir over ssh, live output, rc passed through → sync down; `--get PATH` also fetches an ignored path; `--no-sync` skips both syncs.
- Sync root = git toplevel (a run from a subdir syncs the repo, runs in that subdir remotely); non-git dir = cwd. Remote workdir = `~/offload/<root name>-<sha1(abs root)[:8]>`, persistent ⇒ incremental syncs.
- Git-exact sync: upload set = local `git ls-files -co --exclude-standard` (existing files) + `.git` mirrored (deletions included); after upload the remote deletes its non-ignored files absent from that set (remote git, same ignore sources; local global excludes file shipped along); download set = remote `git ls-files -co --exclude-standard` after the command, `--update`, no deletes, `.git` never returns. Pool hosts need git + GNU coreutils. Non-git dir = rsync mirror with the `.gitignore` dir-merge filter. Tracked files always cross; ignored paths (venvs, toolchains, caches) stay on each side.
- A linked git worktree runs remotely too: the host gets the common git dir + that worktree's own admin dir in git's layout ⇒ its HEAD, index + per-worktree refs (owner ruling: lift the local-only rule).
- Remote runs from one sync root serialize per (host, workdir) on a controller lock; local runs never lock.
- Killing offload (any signal, incl. SIGKILL) kills the command's session, local or remote: the command runs under a watcher that kills its process group at stdin EOF.
- Pool = TOML `[[host]]` tables (`name`, `address` = `[user@]host` or an ssh_config alias — ports + IPv6 via an alias, `slots`). SSH = BatchMode + accept-new host keys.
- Idle task: each pool host may run one designated indefinite task, declared in `machines/<host>/`, in a systemd slice at idle CPU weight ⇒ offload work preempts it at once; offload code unaffected. nixbox's idle task = trading, user `eturkes`; the owner activates + assigns workloads through ChatGPT (Codexify). Trading's own guards gate every start (`.agents/trading-paused` hold, `.agents/operations-active/<unit>` permit); its units stay disabled ⇒ a box reboot ends live trials until Codexify restarts them. Luna (pinned Codex) is held; v1 source-stopped (a reviewed v2 successor precedes any start).
- Pool hosts = dedicated machines; LAN-only (nftables: port 22 from 192.168.40.0/24 alone), key-only SSH, no passwords on any account. nixbox accounts: `offload` (offload runs + deploys; wheel, passwordless sudo) + `eturkes` (unprivileged; trading, its idle task, Codexify; home `/home/eturkes` ⇒ trading's tracked absolute paths hold).
- Trading lives on nixbox at `/home/eturkes/Projects/trading`, every file incl. key files (owner ruling over trading's never-copy rule); ChatGPT iterates on it through Codexify on nixbox (single project): every chat's workspace = `~` (catalogue entry `.`, alias `trading`; `worktrees.mode` never), whose `~/AGENTS.md` (agents repo `codex/nixbox/`) routes to `Projects/trading`. Controller copy deleted after a checksum-verified copy (confirm immediately before).
- Pool host OS = NixOS, config declarative in `machines/<host>/`; Wi-Fi secret stays on controller + box (gitignored `wifi.nix`).
- nixbox disk = LUKS2 root, TPM2 auto-unlock bound to PCR 7 + PCR 15 = 0 (volume key measured into PCR 15 at unlock ⇒ a swapped header cannot unseal it) + Secure Boot with own keys (lanzaboote) ⇒ unattended reboots; recovery key on the controller only.
- nixbox compute posture = performance governor + platform profile, PL1 22 W at boot with the CPU's 98 °C TCC pacing it (thermald off: its Dell DPTF policy held PL1 at 9–12 W; lid shut ⇒ cooling-bound at ~17 W), earlyoom, zram, lid/suspend ignored, battery capped 80 % (`charge_types` = Custom); nix-ld + `UV_PYTHON_PREFERENCE=only-managed` so prebuilt wheels run; `/etc/ssl/cert.pem` = the system CA bundle so those pythons' stdlib TLS verifies.
- nixbox runs every project gate; a tool missing there → an image-adopting project adds it to its image, else any project's session adds it in `machines/nixbox/`, GUI apps included. Carried: envfs (`/bin`, `/usr/bin` from the caller's PATH), toolchain managers fetching each repo's pin (elan, rustup + default stable, go `GOTOOLCHAIN=auto`), node 26 for `offload` (trading keeps system node 24), clang, shellcheck, swipl 9.2.9, bwrap, nix-ld libs for headless Chromium, a git identity for `offload` alone, Noto fonts as the controller's defaults (UI suites lay out alike), `time.timeZone` UTC (trading's clocks unchanged).
- Gate image placement (owner): a project's image definition lives in its own repo; adoption per project, not repo-wide policy — a project adopts when it runs on the pool + its results depend on the host (verdicts keyed on the interpreter build, font layout). Use = a per-machine switch (settings `env`; set on cachyos + pool hosts) ⇒ a repo carrying an image still runs native where the switch is unset (Aeon). Wrapper = an offload subcommand (spike `ctr` → e.g. `offload ctr -- <cmd>`), one tested copy installed on the controller + pool hosts, reading the switch + the project's image definition; a project's gate command references it. Distribution (owner) = each host builds the image itself from the synced definition (tag = its content hash), nothing shipped; the definition stays reproducible (inputs pinned: base + uv digests, Python version, `snapshot.debian.org` date; `--timestamp 0`, hash-based bytecode) ⇒ sync check = equal `RootFS.Layers` digest lists across hosts (image ids differ by the base's local tag). Projects stay portable as good engineering, though none is checked out on Aeon.
- Instruction tiers (owner): machine-only facts (pool, offload placement, a tool a pool host lacks) → that machine's user-level `CLAUDE.md`; project + machine facts → the project's `CLAUDE.local.md` (gitignored, unversioned: bcachefs snapshots back it; no agents-repo copy); project-only facts → the repo. `CLAUDE.project.md` stays machine-agnostic (no per-machine split).
- Pool run environment (owner): cross-host parity moves from per-tool nixbox additions to a replicated environment; containerized dev environments = good practice + an orthogonal portability test. PROTOTYPE spike = per-project image alone (Nix two-sided pin dropped): the gate command wraps `podman run` (rootless both sides; offload unchanged), spike image built on the controller + shipped by id (superseded: per-host build, above). Grading check (owner: a cold fill of all 73 D28 revisions in the image ≈ 3–6 h is not needed to confirm the system ⇒ key equality + one replay suffice): in a local clone of cement at its HEAD (verdict store copied; keys path-independent; the live cement root untouched) — (1) `d28-hits` (cement's own `_d28_content_key` + `_d28_verdict`, no replay) on both hosts; (2) one cold D28 revision replayed in the image on the controller (`d28-one`) → its verdict hits on nixbox (`d28-hits` 0 → 1 there; native today 0: nixbox uv 0.11.21 vs 0.13.1 ⇒ different Python builds); (3) `.agent/gate --omit-d28` in the image on both hosts green + wall-clock vs native per host; (4) upkeep per image bump (steps, seconds, bytes shipped). Distribution measured: `podman save | ssh podman load`, a controller-local registry over an ssh reverse tunnel, a per-host build (the ruled one, above).
