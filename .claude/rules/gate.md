# Gate

- Full gate = `.agent/gate` (CI runs the same command, `.github/workflows/gate.yml`): fmt (`golangci-lint fmt --diff`: gofumpt + gci) · lint (`golangci-lint run`, `.golangci.yml`) · tidy (`go mod tidy -diff`) · test (`gotestsum -- -race -shuffle=on -count=1 -parallel 32 ./...`) · build (`CGO_ENABLED=0 go build -trimpath`) · vuln (`govulncheck -test`) · secrets (Betterleaks over HEAD history) · actions (actionlint) · zizmor (`--offline`) · shell (shellcheck `-S warning` over tracked sh/bash-shebang files) · nix (`nixfmt --check` over tracked `*.nix`) · nixlint (statix per `statix.toml` + `deadnix --fail`; generated `hardware-configuration.nix` excluded) · law (`.agent/law`: rule frontmatter, human-facing filler words, `deferred.md` acceptance checks, contract ids in Go tests) · spec-lint. Prints rc + seconds per step, then the 10 slowest tests; rc 0 only when every step passes.
- Fast gate (iteration) = `.agent/gate fast [pkg…]`: fmt + lint + cached tests of those packages (default `./...`) + law + spec-lint. A unit closes on the full gate.
- `CLAUDE.md` `CI gate` = inapplicable here (owner): offload = an infrastructure repo the CI gate serves, its full gate short (≈ 50 s on nixbox, ≈ 3 min as one CI job; e2e tests run in parallel); the clause exists to take long project gates off the controller ⇒ the full gate runs as `offload run -- .agent/gate`. `Gate` CI = a second environment (Ubuntu 26.04 runner: podman 5.7.0 = K11's floor, the runner a systemd service): every `main` push, plus a dispatch for a unit touching podman or systemd behavior (`internal/{ctr,run}`, e2e harness) before its close: `git push -f origin HEAD:ci/<unit>` → `gh workflow run gate.yml --ref ci/<unit>` → `gh run watch --exit-status <id>` (id: `gh run list -w Gate -b ci/<unit> -L1`); green → `git push origin --delete ci/<unit>`.
- Tools = `.agent/tool <name>`: pinned versions, release assets sha256-checked, go-installed ones checked by the Go sumdb, Rust ones (statix, deadnix: no release binaries) built by `cargo install --locked` from a pinned commit id, cached in gitignored `.tools/`. Bump a pin = version + digest (release asset) or commit id (git-built) in `.agent/tool`, then a full gate. Go = `go.mod` `go 1.27.3` (local toolchain auto-fetches); CI pins setup-go to the same + `GOTOOLCHAIN=local`.
- Suppressions name the rule + reason inline (`//nolint:<linter> // why`; `nolintlint` reds a bare or unused one).
- Separate CI: CodeQL (`.github/workflows/codeql.yml`, Go, manual build). Dependabot (`.github/dependabot.yml`) = gomod + github-actions weekly; it never bumps `go.mod`'s `go` line, `.agent/tool` pins (zizmor included), `runs-on` runner labels or nixbox's lanzaboote tag (`machines/nixbox/secureboot.nix`) → those move by hand, flagged weekly by `.agent/pins` (`.github/workflows/pins.yml`; red = a pin behind; `runs-on` labels vs the newest GA x64 `ubuntu-NN.04` of actions/runner-images' README).
- nixbox's nixos-unstable rev (`machines/nixbox/configuration.nix`) = frozen, unflagged: it supplies `swi-prolog` = cnl-ckc's SWI-Prolog pin (its identity gate refuses any other version) + a `uv` newer than 26.05's. Move it only when one of those must change — cnl-ckc's pin moves, a carried package needs a fix or newer release — to a rev whose `swi-prolog` equals cnl-ckc's pin, then `deploy` + cnl-ckc's gate on nixbox; drop it once the box's channel ships both.
